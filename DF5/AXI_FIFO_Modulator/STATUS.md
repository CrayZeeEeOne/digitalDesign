# DF5 — MicroBlaze: TFT (ST7789) + microSD + I/Q-запис → RTL DSP у реальному часі

> **Версія v0.10.0, стан на 2026-11-12.** На платі працює вся задача Блоку 3 на справжньому записі:
> `CAPTURE.IQ8` (Pluto SDR, 16.7 с, 4.5 МВід/с) іде з microSD нативною 4-бітною шиною прямо в DSP
> у PL **у реальному часі**. DSP сам знаходить пакети Alarm-Beacon, що стрибають по 15 каналах,
> перестроює демодулятор, знебілює PN9 і перевіряє CRC16. За один прохід файлу приймаються всі
> 59 пакетів запису (CRC16 і CRC8 OK, послідовність каналів 58/58). На дисплеї — 6 екранів:
> RAW I/Q, BITS (поля кадру), FFT, WATERFALL (увесь файл), SD CARD, FFT+WF.
> Постановка задачі: `../readme.md`. Повний опис коду: [`docs/how_it_works.md`](docs/how_it_works.md).

Платформа: PA35T-StarLite, `xc7a35tfgg484-2`, топ `microblaze_wrapper`, Vivado/Vitis 2025.2.1.
MicroBlaze 100 МГц з апаратними множником, дільником і barrel shifter, 64 КБ LMB BRAM (код + дані +
стек), без кешів. Дисплей ST7789 320×240 (ROT_90), SPI 25 МГц. microSD — нативна шина SD, 4 біти, 25 МГц.

## Що зараз у залізі (Block Design `microblaze`)
| Блок | Адреса | Що робить |
|---|---|---|
| `microblaze_0` + LMB BRAM | `0x0000_0000`–`0x0000_FFFF` | 64 КБ на код, дані та стек |
| `tft_top` (`spi_tft_ctrl`) | `0x0001_0000` | AXI4-Lite → SPI master до ST7789, TX FIFO 16 байт, ID `0x5F778901` |
| `system_ctrl_top` | `0x44A1_0000` | кнопки K1/K2 з антидребезгом, LED, лічильник тактів |
| `sd_host_top` (`sd_host`) | `0x44A2_0000` | microSD, нативна 4-бітна шина: команди + блок 512 Б для FatFs; потік файлу CMD18 → FIFO 16 КБ → int8/int16 → темп 4.5 МВід/с → M_AXIS; ID `0x53440001` |
| `dsp_top` (`dsp_regs`) | `0x44A4_0000` | вхід ×64, FFT-256 і waterfall на всю смугу, пошук hop-каналу (`dsp_hop`), лінія затримки 4096, демодулятор з PN9/CRC16, захоплення по пакету; ID `0x44535002` |
| `clk_wiz`, `proc_sys_reset`, `mdm`, AXI interconnect | — | такт 100 МГц, скиди, JTAG-дебаг |

Мапи регістрів: `dsp_top` і `sd_host` — у шапках `dsp_regs.sv`, `sd_host.sv` і в
[`docs/dsp_rtl.md`](docs/dsp_rtl.md); TFT — [`docs/block1_tft.md`](docs/block1_tft.md);
system_ctrl — `vitis/src/hal/system_ctrl.h`.

## Версії: що означає кожна цифра

Одна версія на весь проєкт: **`vMAJOR.MINOR.PATCH`**. Бітстрім і прошивка (ELF) мають одну версію,
бо працюють лише в парі: прошивка знає адреси й регістри конкретного Block Design.

### MAJOR — який блок ТЗ здано на платі
MAJOR рахує блоки з `../readme.md`, що пройшли **всі** свої критерії готовності на реальній платі
(не в симуляції). Тобто MAJOR відповідає на питання «що вже можна показати як готове».

| MAJOR | Що означає |
|---|---|
| `0.x.x` | bring-up: щось працює, але жоден блок ТЗ ще не прийнято повністю (**ми тут**) |
| `1.x.x` | Блок 1 здано: TFT ініціалізується без зависань, `TFT TEST` і кольорові області, SPI-сигнали перевірені осцилографом/ILA, є приклад використання драйвера |
| `2.x.x` | Блок 2 здано: FatFs читає файл блоками до EOF, коректні помилки (нема карти / mount / open / read), `test.img` RGB565 з SD без спотворень на TFT |
| `3.x.x` | Блок 3 здано: I/Q-файл із SD → replay → RTL-демодулятор **у залізі** → декодовані пакети + графіки на TFT |
| `4.x.x`+ | зміни після здачі, що ламають сумісність із попереднім MAJOR (інша плата/частина, інший формат I/Q-файлу тощо) |

MAJOR ніколи не підіймається «за обсяг роботи», лише за прийнятий на платі блок. Блок 3 по суті
працює на платі (v0.10.0), але Блоки 1 і 2 ще не здані за своїми критеріями (`TFT TEST`, `test.img`),
тому MAJOR поки 0.

### MINOR — нова можливість або зміна інтерфейсу між залізом і прошивкою
MINOR росте, коли з'являється щось нове, що видно на платі чи в симуляції, **або** коли змінюється
контракт між RTL і C: Block Design, адреси, мапа регістрів, піни.

* новий RTL-блок чи тестбенч, новий екран переглядача, нова функція драйвера;
* додано/прибрано IP у BD, змінено адресу або біти регістра, змінено `.xdc`-піни.

Правило сумісності: **бітстрім і ELF з однаковим `MAJOR.MINOR` сумісні між собою**. Після зміни MINOR
треба перезібрати і бітстрім, і прошивку (`build.bat -board`).

### PATCH — виправлення без нових можливостей
PATCH росте за фікси, які не додають функцій і не змінюють інтерфейс RTL↔C: виправлення помилки,
таймінгу, геометрії, значень після скиду, скриптів збірки. Можна оновити щось одне — тільки бітстрім
або тільки ELF — у межах того самого `MAJOR.MINOR`.

Зміни лише в документації (`STATUS.md`, `docs/`) версію не змінюють.

### Як ставити версію
1. Запис у «Історія версій» нижче: версія, дата, що змінилось, що перевірено (симуляція / плата).
2. Після того як зміну перевірено, git-тег на коміт: `git tag v0.4.1`.
3. Сумнів між MINOR і PATCH → питання одне: «чи треба після цього перезбирати *обидві* частини?»
   Так → MINOR, ні → PATCH.

## Історія версій

* **v0.1.0** (2026-09-21 … 2026-10-12, коміти `296f843` … `07eaf2f`) — каркас DF5. Скриптовий
  Vivado-потік (`build.bat -syn/-impl/-xsa/-all/-board`), `spi_tft_ctrl` + `tft_top`, `system_ctrl` з
  кнопками, BD з MicroBlaze; бітстрім зібрано, таймінг закрито. У симуляції — RTL 2-FSK/GFSK
  демодулятор: `demod_nco_mixer` → `demod_cic3` → `demod_discriminator` (CORDIC atan2) → `demod_power`
  → `demod_bit_decoder`, обгортки `rtl_demod_regs`/`rtl_demod_top` і `iq_stream_*`; `sim.iq`
  (`iqgen.py`), золота модель `demod_model.py`, еталонні графіки `rtl_demod_plots.html`.
* **v0.2.0** (2026-10-13) — новий застосунок: `graph_viewer` на MicroBlaze, 12 екранів як у HTML,
  перемикання K1/K2. У моделі детектора виправлено: `age` завжди був 0 (SYNC/PRE/PKT не вмикались),
  оцінка шуму підтягувалась до сигналу (burst гас через ~0.5 мс), провали посеред пакета → заморожування
  шуму під час burst і hangover 16 відліків. Тестове джерело в `main.c`: 2-FSK на −250 кГц, ±50 кГц,
  пакети 192 символи / паузи 128. Перевірено на платі (JTAG) і ПК-рендером.
* **v0.3.0** (2026-10-13) — нова поведінка: графіки не прокручуються. Один запис 36.4 мс (≈2 пакети)
  після старту, кожен графік — увесь запис на одному екрані (min/max на колонку), перемальовування

  `dsp_top` (генератор `iq_gen`, демодулятор `rtl_demod`, захоплення `dsp_capture`, FFT і waterfall

  MicroBlaze отримав апаратні множник/дільник/barrel shifter. `tb_dsp_top` + `check_dsp_capture.py`
  (біт у біт).
* **v0.9.0** (2026-10-28, коміти `c352e62`, `1195966`) — живий режим: генератор у реальному часі
  (4.5 МВід/с), спектр кожного блоку в кільце на 256 рядків, захоплення перезапускається після кожного
  зчитування, пауза K2. Екрани без мерехтіння (малювання колонками/рядками в одному вікні), SPI TFT
  25 МГц, ~15 кадрів/с. Вікно спектра навколо каналу (`SPEC_BIN0`). Документ `docs/how_it_works.md`.
* **v0.10.0** (2026-11-01 … 2026-11-12, коміт `f02e430`) — справжній запис замість генератора:
  * **Сигнал:** `CAPTURE.IQ8` — запис Pluto SDR (`capture_300MB.iq`), переведений `tools/iq16to8.py`
    у int8 без втрат (значення ±104). Пакети Alarm-Beacon: 15 hop-каналів 865.3…869.5 МГц,
    преамбула 10×0xAA, sync 0x91D3, 16 байт із PN9, CRC16 радіо (старт 0x1D0F) і CRC8 кадру.
  * **`sd_host`** (новий): нативна 4-бітна шина SD у PL замість AXI Quad SPI і `iq_stream`. Команди
    й блоки для FatFs, потік файлу CMD18 прямо в `dsp_top` з темпом рівно 4.5 МВід/с, зупинка тактової
    між блоками, коли FIFO повний. Явні `IOBUF` (через `? : 'z` у модулі BD синтез ставив OBUF).
    Тестбенч `tb_sd_host` з моделлю картки `sd_card_model.sv` (21/21 PASS).
  * **`dsp_hop`** (новий): по FFT кожного блоку рівні 15 каналів → поріг (шум ×32, не менше 256) →
    2 блоки поспіль → NCO демодулятора на канал пакета і запуск захоплення. Лінія затримки 4096
    відліків перед демодулятором. Генератор `iq_gen` прибрано.
  * Демодулятор: знебілювання PN9 після sync, CRC16 з залишком 0x1D0F. Вхід ×64 (`IN_SHIFT`).
  * Спектр на всю смугу 4.5 МГц (пара бінів → точка), заморожування кільця + буфер останнього рядка.
  * **Екрани:** BITS — канал, CRC16/CRC8, номер пакета, лічильник тривог, статистика прийому;
    FFT — 5 підписів частоти; WATERFALL — увесь файл (144 рядки по 116.5 мс), шкала в секундах, синій
    фон, сигнал червоний → жовтий, середній рівень кожної частоти віднімається; новий 6-й екран FFT+WF.
  * Файл програється один раз, потім **END**; K1+K2 — знову з початку.
  * Перевірено: `tb_dsp_top` на `hop.iq` (3/3 пакети, канали, звірка з моделлю біт у біт),
    `tb_sd_host`; на платі — 4.50 МВід/с, 59/59 пакетів запису з CRC OK за один прохід.

**Наступні кроки до `v1.0.0`**: тестовий екран `TFT TEST` з кольоровими областями, перевірка SPI-сигналів
(ILA або осцилограф) і запис результату сюди.

## Переглядач сигналу (`vitis/src/app/viewer.c`)
DSP — у PL. Прошивка відкриває `CAPTURE.IQ8` (або `CAPTURE.IQ`, int16, ~0.7× реального часу),
знаходить, де він лежить на картці (FatFs fast seek), запускає потік `sd_host` і лише забирає
результати й малює.

| # | Екран | Що показує | Зум (×1…×16) по |
|---|---|---|---|
| 1 | RAW I/Q | обвідна I і Q 21.8 мс навколо останнього пакета, позначка P1 | часу |
| 2 | BITS | біти слайсера + канал, CRC16, CRC8, номер, лічильник тривог, hex; статистика прийому | часу |
| 3 | FFT | dBFS на всю смугу 865.15…869.65 МГц, маркер піку, 5 підписів частоти | частоті |
| 4 | WATERFALL | увесь файл 0…16.7 с згори вниз, біла лінія — місце програвання | частоті |
| 5 | SD CARD | тест картки, корінь, файл, форматування | — |
| 6 | FFT+WF | FFT зверху, waterfall знизу | частоті |

Стани: **PLAY** (файл іде, K2 — пауза) → **END** (файл закінчився, усе застигло; K1+K2 — знову) і
**PAUSE** (K1+K2 — далі). K1 — наступний екран; K2 — зум (поза PLAY); утримання K1/K2 — прокрутка.

Бюджет пам'яті (64 КБ BRAM, стек від `0xFFF0` донизу):
| Що | Байт |
|---|---|
| код (`.text`, з `-flto`) | 40 604 |
| дані (`.bss`): захоплення 7 КБ, буфер завантаження по JTAG 4 КБ, робоча пам'ять `f_mkfs` 4 КБ, екрани 1.6 КБ, FatFs, журнал пакетів | 20 396 |
| вільно під стек | ≈4.5 КБ |

## Збірка і запуск
Потрібно: Vivado і Vitis 2025.2.1 (`vivado` і `xsct` у `PATH`, `XILINX_VITIS` = каталог Vitis для `mb-gcc`),
плата підключена по JTAG.
```
cd AXI_FIFO_Modulator\scripts
build.bat -board               # усе разом: Vivado (BD з create_bd.tcl → бітстрім → XSA) + прошивка + JTAG
```
Або по кроках:
```
build.bat                      # лише проєкт і Block Design (без синтезу)
build.bat -all                 # Vivado: проєкт → синтез → імплементація → бітстрім → XSA
build.bat -bd                  # те саме, але BD спершу перебудовується з create_bd.tcl
                               #   (після змін create_bd.tcl або RTL-модулів у BD)
build_elf.bat                  # прошивка → vitis\elf\df5_app.elf
xsct run_board.tcl             # залити бітстрім + ELF і запустити MicroBlaze
sim_tb.bat tb_dsp_top          # тестбенч DSP + звірка з моделлю (також tb_sd_host)
```
Картка: FAT32, у корені `CAPTURE.IQ8` (зробити з запису: `python tools\iq16to8.py capture_300MB.iq CAPTURE.IQ8`).
Після першого запуску прошивки зі старою (SPI) версією картку треба вийняти/вставити або вимкнути
плату: з SPI-режиму картка виходить лише після вимкнення живлення.

Перевірка екранів без плати (після будь-якої зміни в `vitis/src`):
```
tools\host_sim\run_host_sim.bat           # рендер екранів → out\, golden.md5
tools\host_sim\run_host_sim.bat -update   # прийняти нову картинку як еталон (після навмисної зміни)
```
Після правок BD у GUI (`build.bat -gui`) перегенеруй `scripts/create_bd.tcl`:
`write_bd_tcl -force -no_project_wrapper scripts/create_bd.tcl`, потім поверни у файл заголовок,
`set run_remote_bd_flow 0` і виклик `cr_bd_microblaze ""` в кінці.

## Відомі проблеми / TODO
