# Блок 1 — TFT: SPI RTL, C-драйвер і тест виводу

Архітектура software-driven: MicroBlaze формує пікселі й текст у C,
`spi_tft_ctrl` виконує роль байтового транспорту до ST7789. Команди від
даних відрізняє біт `DC` у регістрі керування.

```
MicroBlaze ──AXI4-Lite──> spi_tft_ctrl ──SPI──> ST7789
                              │
                       TX FIFO (16 байт)
```

## Файли

| Файл | Призначення |
|---|---|
| `rtl/spi_tft_ctrl.sv` | SPI master + регістри AXI4-Lite |
| `rtl/tft_top.v` | Verilog-обгортка для Block Design |
| `rtl/tb_spi_tft_ctrl.sv` | тестбенч RTL |
| `sw/spi_tft.c/.h` | низький рівень: регістри, передача байтів |
| `sw/tft.c/.h` | ST7789: ініціалізація, вікно, примітиви, текст |
| `sw/font5x7.c/.h` | растровий шрифт 5×7, ASCII 0x20–0x5F |
| `sw/main.c` | тест виводу |

## Мапа регістрів

Базова адреса береться з `xparameters.h`. Діапазон — 32 байти.

### 0x00 CTRL (RW)

| Біт | Назва | Опис |
|---|---|---|
| 0 | `enable` | вмикає SPI; при 0 `SCLK` стоїть і FIFO не стікає |
| 1 | `dc` | 0 = команда, 1 = дані |
| 2 | `rst_n` | апаратний скид дисплея, активний нулем |
| 3 | `cs_n` | ручне керування `CS` (діє при `cs_auto` = 0) |
| 4 | `cs_auto` | 1 = `CS` активний, поки є що передавати |
| 5 | `blk` | підсвітка, 1 = увімкнена |

Після скиду `rst_n` = 1 і `blk` = 1 — дисплей не в скиді, підсвітка
увімкнена одразу після конфігурації FPGA. Апаратний скид панелі робить
сам `tft_init()` (`spi_tft_hw_reset`).

### 0x04 CLKDIV (RW)

```
f_sclk = f_aclk / (2 * (CLKDIV + 1))
```

При 100 МГц: `CLKDIV = 1` → 25 МГц, `CLKDIV = 3` → 12.5 МГц.
Для bring-up бери нижчу частоту, потім піднімай.

### 0x08 TXDATA

Запис молодшого байта штовхає його в TX FIFO. Якщо FIFO повний — запис
ігнорується, тому драйвер спершу перевіряє `tx_full`.

Читання повертає останній байт, зсунутий з `MISO`.

### 0x0C STATUS (RO)

| Біт | Назва |
|---|---|
| 0 | `busy` — іде передача |
| 1 | `tx_full` |
| 2 | `tx_empty` |
| 7:4 | `tx_level` — скільки байтів у FIFO |

### 0x10 ID (RO)

Повертає `0x5F778901`. Перше, що читає драйвер: якщо значення інше —
проблема в адресному мапінгу або з'єднанні AXI, а не в дисплеї.

## Режим SPI

Mode 0: `CPOL = 0`, `CPHA = 0`, MSB first. Дані виставляються по спаду
`SCLK`, приймач захоплює їх по наростаючому фронту — як вимагає ST7789.

## Піни на PA35T-StarLite

ST7789 висить на роз'ємі JM1, банк 16, `LVCMOS33`:

| Сигнал | JM1 | Пін | Порт RTL |
|---|---|---|---|
| SCL | 3 | `E16` | `tft_sclk` |
| SDA | 4 | `F13` | `tft_mosi` |
| RES | 5 | `D16` | `tft_rst_n` |
| DC | 6 | `F14` | `tft_dc` |
| CS | 7 | `C13` | `tft_cs_n` |
| BLK | 8 | `D14` | `tft_blk` |

`MISO` модуль не має — вхід `tft_miso` прив'яжи до `1'b0` у Block Design.

Такт: диференційна пара `R4`/`T4`, 200 МГц, `DIFF_SSTL15`.
Скид: `R14`, `LVCMOS33` з підтяжкою, активний низьким рівнем.

## Порядок bring-up

1. Прочитати `ID` → перевірка шини.
2. Задати `CLKDIV`, підняти `enable` і `cs_auto`.
3. `spi_tft_hw_reset()` — імпульс `RESET` з паузою 120 мс.
4. `tft_init()` — `SWRESET`, `SLPOUT`, `COLMOD = 0x55`, `MADCTL`, `DISPON`.
5. `spi_tft_backlight(&spi, 1)` — підсвітка **після** ініціалізації.
6. Кольорові смуги → перевірка порядку каналів і орієнтації.
7. Текст `TFT TEST`.

## Що перевіряти, якщо не працює

| Симптом | Де шукати |
|---|---|
| `ID` ≠ `0x5F778901` | базова адреса, AXI-з'єднання в BD |
| `ID` правильний, екран чорний | підсвітка (`blk`), `RESET`, пауза, `DISPON` |
| Видно сміття при вмиканні плати | підсвітка вмикається зарано |
| Сміття на екрані | `CLKDIV` завеликий, перевір на 1 МГц |
| Кольори переплутані | `MADCTL`: біт BGR замість RGB |
| Зображення зсунуте | `x_off` / `y_off` у `tft_t` — залежить від модуля |
| Половина екрана порожня | геометрія: `TFT_WIDTH` / `TFT_HEIGHT` |
| Текст є, заливка повільна | підняти `CLKDIV`, збільшити `FIFO_DEPTH` |

## Запуск тестбенча

```bash
vlog -sv rtl/spi_tft_ctrl.sv rtl/tb_spi_tft_ctrl.sv
vsim -c tb_spi_tft_ctrl -do "run -all; quit"
```

Тестбенч містить власний SPI-приймач: збирає байти по фронту `SCLK`,
складає їх у чергу разом зі станом `DC` і звіряє з очікуваними. Окремо
перевіряє виміряний період `SCLK` проти `CLKDIV`.

## Інтеграція в Block Design

Так само, як робили з PWM-блоком:

1. Додати `spi_tft_ctrl.sv` (File Type: **SystemVerilog**) і `tft_top.v`
   (File Type: **Verilog**) у Design Sources.
2. Синтез — щоб Vivado побудував ієрархію.
3. На канві BD: правою кнопкою → **Add Module...** → `tft_top`.
4. **Run Connection Automation** — підключить `S_AXI` до інтерконекта.
5. `Make External` для `tft_sclk`, `tft_mosi`, `tft_cs_n`, `tft_dc`,
   `tft_rst_n`, `tft_blk`. `tft_miso` прив'язати до `1'b0`.
6. **Перейменувати зовнішні порти** у External Port Properties під імена
   з `tft.xdc`: `lcd_scl`, `lcd_sda`, `lcd_res`, `lcd_dc`, `lcd_cs`,
   `lcd_blk`, `clk_200_p`/`clk_200_n`, `rst_n`. Інакше Vivado додасть
   суфікси `_0` і `get_ports` нічого не знайде.
7. Піни в `.xdc` — **без квадратних дужок**, порти скалярні.

Діапазон в Address Editor постав ≥ 4K (мінімум Vivado для AXI-слейва).
